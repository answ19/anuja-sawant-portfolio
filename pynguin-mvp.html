Automated testing / Software architecture

Pynguin-MVP.

A lightweight Python test generator that discovers functions, explores candidate inputs, retains coverage-improving tests, and produces executable test suites and reports.

Pythonpytestcoverage.pyCLIHTML reports
Explore the source code ↗Read IEEE research ↗
01 / Motivation

Make testing gaps visible.

Manually authoring tests for every function, argument boundary, and failure condition can take substantial effort. I explored a small, approachable implementation of automated test generation concepts that could reveal untested paths and produce readable test output.

02 / Approach

From Python functions to pytest.

  1. Discover functions and parameters through reflection and type hints.
  2. Generate varied candidate inputs, including boundary-oriented and random scenarios.
  3. Measure execution coverage and keep tests that add line coverage.
  4. Export runnable pytest assertions and coverage metadata.
  5. Build an HTML report to make outcomes easier to inspect.
03 / Documented sample

Evidence, with context.

For one example triangle.py target module, the repository README documents the following run:

Target:           triangle.py
Functions found:  1
Tests retained:   4
Tests passing:    4
Line coverage:    8 / 10 lines (80%)
Artifacts:        test_generated.py, coverage.json, report.html

This is a result for one documented sample module, not an average across projects or a claim of broad production readiness.

04 / Research connection

From a build to a research question.

My related coauthored paper, “Pynguin-MVP: Automated Test Generation for Lightweight Architectural Validation,” explores how generated tests can support lightweight feedback on architectural assumptions and unexpected software interactions.
