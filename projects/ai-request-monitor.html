AI Request Monitor.

A small, explainable security checkpoint for AI application inputs—designed around clear risk scores, human-readable reasons, and event logging.

PythonFastAPIPydanticStreamlitpytestRule-based prototype
Explore the source code ↗View resume
01 / Problem

Know what an input is asking.

Prompt-injection attempts may try to override instructions, extract hidden prompts, or redirect an LLM application. The challenge for this prototype was to identify known suspicious patterns before model processing, while keeping the screening result understandable.

02 / Approach

An explainable request pipeline.

  1. Normalize input text to make simple rules easier to apply.
  2. Check for predefined prompt-injection patterns, including instruction overrides and system-prompt exposure.
  3. Return a risk score from 0 to 100, flagging scores at or above the prototype's threshold of 60.
  4. Record a timestamp, score, and human-readable reasons as structured JSONL events.
  5. Provide POST /analyze, request validation, a local Streamlit interface, and automated tests.
03 / Example response

What the API returns.

Illustrative request and response shown in the public project README (not a live hosted endpoint).

04 / Engineering judgment

Clarity over false confidence.

The design is intentionally rule-based. It can be useful for exploring observability and known attack patterns, but it is not a universal prompt-injection defense or a production-validated security system.

What I'd explore next

Broader pattern evaluation, hybrid detection, monitoring analytics, rate limiting, and potential RAG integration.
